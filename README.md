# Smart Cleaning — приложение клинера (MVP)

Telegram Mini App, в котором клинер сам берёт заказ из ленты, отмечается на объекте, делает фото «до» и «после», проходит чек-лист и сдаёт работу. Клиент оценивает работу в боте, администратор выплачивает вручную.

```
webapp/                      Mini App (статичный сайт → GitHub Pages)
supabase/migrations/         база данных, одна миграция
supabase/functions/api       API для Mini App (проверка подписи Telegram)
supabase/functions/bot       вебхук бота: регистрация, заказы, чат, оценки, выплаты
supabase/functions/cron      напоминания и автоприёмка, раз в 10 минут
.github/workflows/pages.yml  автопубликация webapp на GitHub Pages
```

## Запуск за 7 шагов

Нужно: аккаунт Supabase, аккаунт GitHub, Telegram. Supabase CLI ставится одной командой: `brew install supabase/tap/supabase`.

### 1. Бот

1. В [@BotFather](https://t.me/BotFather): `/newbot` → имя и username. Сохраните **токен бота** (в репозиторий не коммитить) и **username**
2. Узнайте свой Telegram ID (например, у [@userinfobot](https://t.me/userinfobot)) — это будет администратор. Несколько админов — через запятую.

### 2. Проект Supabase и база

1. Создайте проект на [supabase.com](https://supabase.com). Регион — ближайший (Frankfurt).
2. **SQL Editor** → вставьте содержимое `supabase/migrations/0001_init.sql` → **Run**.
3. Запишите **Project ref** (из адреса проекта: `https://<ref>.supabase.co`).

### 3. Секреты функций

Придумайте две длинные случайные строки: `WEBHOOK_SECRET` и `CRON_SECRET` (например, `openssl rand -hex 24`).

```bash
supabase login
supabase link --project-ref <ref>

supabase secrets set \
  BOT_TOKEN="123456:ABC..." \
  BOT_USERNAME="smartcleaning_cleaner_bot" \
  ADMIN_TG_IDS="111111111,222222222" \
  WEBAPP_URL="https://<github-логин>.github.io/<репозиторий>/" \
  WEBHOOK_SECRET="..." \
  CRON_SECRET="..." \
  KASPI_PAY_URL="https://pay.kaspi.kz/..."     # необязательно: ссылка на оплату для клиента
```

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` Supabase подставляет сам.

### 4. Деплой функций

Флаг `--no-verify-jwt` обязателен: функции проверяют доступ сами (подпись Telegram, секрет вебхука, секрет cron).

```bash
supabase functions deploy api  --no-verify-jwt
supabase functions deploy bot  --no-verify-jwt
supabase functions deploy cron --no-verify-jwt
```

### 5. Вебхук бота

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -d "url=https://<ref>.supabase.co/functions/v1/bot" \
  -d "secret_token=<WEBHOOK_SECRET>" \
  -d 'allowed_updates=["message","callback_query"]'
```

Ответ `"ok":true` — бот подключён.

### 6. Mini App на GitHub Pages

1. В `webapp/config.js` впишите адрес API: `https://<ref>.supabase.co/functions/v1/api`.
2. Залейте папку проекта в репозиторий GitHub (ветка `main`).
3. **Settings → Pages → Source: GitHub Actions.** После пуша workflow опубликует `webapp` по адресу `https://<логин>.github.io/<репозиторий>/`. Этот адрес должен совпадать с `WEBAPP_URL` из шага 3.
4. В @BotFather: `/mybots` → бот → **Bot Settings → Menu Button** → адрес Mini App и текст «Заказы». Тогда кнопка приложения будет в каждом чате с ботом.

Если хотите закрыть API для чужих сайтов, добавьте секрет `WEBAPP_ORIGIN="https://<логин>.github.io"` и передеплойте `api`.

### 7. Напоминания по расписанию

В Supabase: **Database → Extensions** → включите `pg_cron` и `pg_net`. Затем в SQL Editor:

```sql
select cron.schedule(
  'cleaner-app-cron',
  '*/10 * * * *',
  $$
  select net.http_post(
    url     := 'https://<ref>.supabase.co/functions/v1/cron',
    headers := '{"x-cron-secret": "<CRON_SECRET>", "content-type": "application/json"}'::jsonb,
    body    := '{}'::jsonb
  );
  $$
);
```

Проверить вручную: `curl -X POST https://<ref>.supabase.co/functions/v1/cron -H "x-cron-secret: <CRON_SECRET>"` — вернёт список задач и сколько заказов обработано.

### 8. Заказы из CRM Big Prodast

Заказы создаются сами из сделок CRM: cron раз в 10 минут забирает открытые сделки с этапа `CRM_STAGE` и по каждой один раз создаёт заказ. Связь идёт через MCP CRM (`/api/mcp`): он работает на любом тарифе, а REST API — только на «Максимальной».

Секреты функций:

| Секрет | Что это |
| --- | --- |
| `CRM_API_KEY` | ключ `bp_…` из CRM → Настройки → API и MCP |
| `CRM_STAGE` | id этапа, с которого берём сделки («Передать клинеру») |
| `CRM_STAGE_TAKEN` | id этапа, куда двигать сделку, когда клинер взял заказ (необязательно) |
| `CRM_STAGE_DONE` | id этапа, куда двигать сделку после приёмки работы (необязательно) |
| `CRM_PAYOUT_PERCENT` | выплата клинеру в % от суммы сделки, если нет поля «Выплата клинеру» |
| `CRM_FIELDS` | свои названия полей, JSON: `{"address":["Адрес уборки"]}` (необязательно) |

Что берётся из сделки: дата записи, сумма (цена клиенту), имя и телефон клиента. Из полей карточки клиента (CRM → Настройки → Поля): «Адрес», «Район», «Площадь», «Комнат», «Пожелания», «Выплата клинеру». Если чего-то не хватает, админу приходит сообщение со списком; после правки сделки заказ создастся сам.

Этапы указывайте **id**, а не названием: среда Edge Functions портит кириллицу в секретах. id этапов — в `crm_directory` MCP или в ответе `?crm=discover`. Если перенос сделки не удался, cron повторяет его каждые 10 минут (таблица `crm_sync_errors`).

Проверить настройку: `curl -X POST "https://<ref>.supabase.co/functions/v1/cron?crm=discover" -H "x-cron-secret: <CRON_SECRET>"` — покажет этапы и названия полей (без данных клиентов).

## Как этим пользоваться

**Клинер.** Пишет боту `/start` → делится контактом → админу приходит заявка. После пробной уборки админ отправляет `/activate <tg_id>`, и клинеру открываются заказы.

**Администратор** (команды в боте):

| Команда | Что делает |
| --- | --- |
| `/new дата время \| район \| адрес \| м² \| комнат \| цена клиенту \| выплата клинеру \| клиент \| пожелания` | создаёт заказ, рассылает клинерам, даёт ссылку для клиента |
| `/orders` | заказы на сегодня и завтра со статусами |
| `/payouts` | очередь выплат с кнопкой «Выплачено» |
| `/activate <tg_id>`, `/block <tg_id>` | допуск и блокировка клинера |

Пример: `/new 24.11 10:00 | мкр. Строитель | ул. Примерная 1, кв 2, подъезд 1, этаж 3 | 54 | 2 | 18000 | 12000 | Айгерим, +77010000000 | дома кот`

**Клиент.** После `/new` админ получает ссылку вида `t.me/<бот>?start=c_...` и отправляет её клиенту в WhatsApp. Клиент нажимает — и получает в бот подтверждение, фото результата и кнопки оценки. Если клиент ссылку не открыл, фото и кнопки «Принять / На переделку» приходят админу.

Минимальный уровень клинера для заказа (`min_level`: `new` / `standard` / `pro`) и прочие поля можно поменять прямо в таблице `orders` в Supabase.

## Как идёт заказ

`open` → клинер «Беру» → `taken` → подтверждение накануне до 21:00 → `confirmed` → «Выехал» → `on_way` → «Я на месте» + геолокация → `onsite` → фото «до», чек-лист, фото «после» → `submitted` → оценка 4–5 или 2 часа тишины → `accepted` → админ выплатил → `paid`.

Оценка 1–3 или «Есть замечание» → `rework` → клинер переделывает и сдаёт снова. Отказ или нет подтверждения до 21:00 → заказ возвращается в ленту, при отказе меньше чем за сутки рейтинг −0,2. Если заказ взят меньше чем за 12 часов до начала или вечером накануне, отдельное подтверждение не требуется.

Каждая смена статуса пишется в `order_events` — это история для разбора споров. Переписка клинера и клиента через бота хранится в `messages`.

## Чек-лист перед тестом

1. Себя добавить в `ADMIN_TG_IDS`, со второго аккаунта зарегистрироваться клинером и активировать.
2. `/new` на завтра → уведомление пришло клинеру → «Беру» → адрес открылся.
3. Открыть ссылку клиента с третьего аккаунта (или проверить ветку «клиент не в боте»).
4. Пройти «Подтвердить → Выехал → На месте», сделать фото, отметить чек-лист, сдать.
5. Клиентом поставить 5 → у клинера «принято», у админа выплата в `/payouts` → «Выплачено».
6. Повторить с оценкой 2 → переделка → повторная сдача.

## Что сознательно не вошло в MVP

- Автоматические выплаты: админ переводит на Kaspi вручную и жмёт «Выплачено».
- Ранний доступ уровня Pro к ленте (на 15 минут раньше) — поле уровня уже есть, логику добавим после теста.
- Отдельная админка: заказы, клинеры и штрафы правятся в таблицах Supabase.
- Фото в бот от клинера: только через приложение.

Ставку клинеру за м², размеры штрафов и пороги уровней утвердить по итогам теста (сейчас: штраф 0,2; Standard — 5 заказов и рейтинг от 4,5; Pro — 30 заказов и от 4,8; меняется в функции `recalc_cleaner`).
